# 多螢幕切換與數值傳遞

# 本章目標

1. 理解 **多螢幕 (Multi-Screen)** 架構。
2. 學習 **切換螢幕** 與 **關閉螢幕**。
3. 掌握 **數值傳遞 (Start Value)** 技巧。
4. 認識 **TinyDB** 跨頁存取。

---

# 為什麼需要多個螢幕？

目前的 App 都只有一頁 (Single Page)。
但真正的 App 結構通常是：

- **Screen1 (首頁)**: 選單、登入。
- **Screen2 (主功能)**: 遊戲、工具。
- **Screen3 (設定)**: 修改開關。
- **Screen4 (關於)**: 作者資訊。

在 AI2，我們可以新增很多個 **Screen** 來管理不同頁面。

---

# 新增螢幕 (Add Screen)

1. 在 Designer 上方綠色標題列。
2. 點選 **"Add Screen"**。
3. 輸入名稱 (例如 `Screen_Game`)。
   - <mark>注意：Screen1 是預設首頁，不能改名，也不能刪除！</mark>
4. 畫面變全白，進入新的一頁。
5. 可以透過下拉選單在不同 Screen 間切換。

---

# 切換指令 (Open Screen)

在 Control 抽屜裡：

### 1. 開啟新頁面
`<open another screen screenName "Screen2">`
- `screenName`: 必須接一個 **文字 (Text)** 積木。
- 內容要是螢幕名稱，**大寫小寫要完全一樣** (建議用複製貼上的)。

### 2. 關閉目前頁面
`<close screen>`
- 這是「返回」的意思。
- 執行後，目前的螢幕會關閉，回到**上一個**打開它的螢幕。

---

# 記憶體管理：堆疊 (Stack)

想像螢幕是盤子，你每開一個新螢幕，就是**疊一個盤子上去**。

- **危險做法**：Screen1 開 Screen2，Screen2 又開 Screen1...
  - 盤子越疊越高，最後倒塌 (記憶體不足 Crash)。

- **正確做法**：
  - 要去下一頁 -> `open screen`
  - 要回上一頁 -> `close screen` (把盤子拿掉)

> 盡量不要讓使用者在兩個螢幕間無限循環開啟。

---

# 跨螢幕傳值 (Pass Value)

場景：在 Screen1 輸入名字，跳到 Screen2 顯示「你好，XXX」。
問題是：**Screen2 讀不到 Screen1 的變數！** (變數是區域的)

### 解法 A：Start Value (接力棒)
1. **傳送 (Screen1)**:
   `<open another screen with start value>`
   - screenName: "Screen2"
   - startValue: `txt_name.Text`

2. **接收 (Screen2)**:
   - 在 `Initialize` 裡，使用 `get start value` (Control 抽屜)。
   - `set Label.Text to get start value`。

---

# 傳遞多個數值？

Start Value 只能傳**一個**東西。
如果我要傳「姓名」和「分數」怎麼辦？

### 技巧：打包成清單 (List)
1. **傳送**: `make a list (name, score)` 當作 startValue。
2. **接收**: 
   - `get start value` 收到的是一個 List。
   - 用 `select list item index 1` 拿姓名。
   - 用 `select list item index 2` 拿分數。

---

# 解法 B：TinyDB (共用資料庫)

如果資料很多，或是要在好幾個螢幕間共用 (例如：背景音樂設定)。

用 **TinyDB** 是最方便的！

1. **存 (Screen1)**: `TinyDB.StoreValue tag "name" value "Tom"`
2. **切換螢幕**...
3. **讀 (Screen2)**: `TinyDB.GetValue tag "name"`

TinyDB 的資料是存在手機硬碟裡的，所有 Screen 都讀得到，甚至重開機都還在！

---

# 進階架構：假多螢幕 (Fake Screens)

有些高手不喜歡用多個 Screen (因為切換時會黑屏一下，體驗不好)。
他們會用 **Layout** 來做「假」切換。

1. 放三個 VerticalArrangement (滿版)，分別代表三頁。
2. 把 layout2, layout3 的 **Visible** 設為 False (隱藏)。
3. 當按鈕按下時：
   - 把所有 layout 隱藏。
   - 只把目標 layout 的 Visible 設為 True。

這樣切換是**瞬間**的，而且變數可以共用！(推薦給進階同學)

---

# 重點回顧

1. **Screen Lifecycle**: 注意開啟與關閉的順序，避免記憶體洩漏。
2. **Start Value**: 適合傳遞少量、單次的資料。
3. **TinyDB**: 適合傳遞全域設定、大量資料。
4. **List Packing**: 用清單把多個資料打包，一次傳送。
