# 今天的目標

<br>

今天**不是**要你從零寫出一個遊戲。

今天的目標是：

1. **理解遊戲的基本概念**（Canvas、Game Loop、狀態）
2. **學會對 AI 下正確的 Prompt**
3. **讓 AI 幫你生出一個可以玩的遊戲**

> 工程師的能力，不在於「什麼都自己打」，
> 而在於「**清楚知道自己要什麼**」。

---

# Canvas 是什麼？

<br>

`<canvas>` 是 HTML 裡的一塊**畫布**。

把它想像成網頁上的一個「**電視螢幕**」：

- 它本身什麼都不會畫
- JavaScript 告訴它：**在哪個位置，畫什麼形狀**
- 遊戲畫面就是在這塊畫布上，**不斷清掉、重新繪製**

> 就像動畫膠卷，每一格都重新畫一次——
> 每秒畫 60 格，眼睛就看不出來是一張張切換的了。

---

# Canvas 座標系統

<br>

Canvas 的座標從**左上角 (0, 0)** 開始：

```
(0,0) ────────────────→  X 增加（往右）
  │
  │      ● (200, 150)
  │
  ↓
  Y 增加（往下）
```

- 往右走，X 變大
- 往下走，Y 變大（跟數學的 Y 軸**相反**！）

理解這個座標，才能告訴 AI「玩家要在畫面底部的中間」是什麼意思。

---

# Game Loop 是什麼？

<br>

遊戲程式的核心是一個**不斷重複的循環**，每秒大約執行 60 次：

```
┌────────────────────────────────┐
│  每一幀 (Frame) 重複做：       │
│                                │
│    1. UPDATE  更新所有物件     │
│    2. DRAW    重新繪製畫面     │
│                                │
│  ← 無限重複，直到遊戲結束 →   │
└────────────────────────────────┘
```

這就是所有遊戲的運作方式——
從《貪吃蛇》到《原神》，**骨架都一樣**。

---

# UPDATE 在做什麼？

<br>

Update 是每一幀的**邏輯計算階段**，負責回答：

- **玩家移動了嗎？** → 根據按鍵更新玩家的 X、Y 座標
- **障礙物在哪？** → 每幀讓它的 Y 座標加一點（向下移動）
- **碰到東西了嗎？** → 檢查玩家和障礙物的位置是否重疊
- **分數要更新嗎？** → 成功閃過就加分
- **要不要生新的敵人？** → 每隔幾幀生成一個新障礙物

> Update 裡**只計算，不畫圖**。
> 計算完才交給 Draw 畫出來。

---

# DRAW 在做什麼？

<br>

Draw 是每一幀的**繪製階段**，負責把 Update 算好的狀態畫出來：

```
1. 清空畫面（把上一幀的畫面全部擦掉）
2. 畫背景
3. 畫所有障礙物（根據它們當前的 X、Y 座標）
4. 畫玩家（根據玩家當前的 X、Y 座標）
5. 畫 UI（分數、生命值、倒數計時）
```

Draw 只是**忠實呈現**目前的狀態，它不做任何邏輯判斷。

> Update 負責「算」，Draw 負責「畫」。
> 分開設計，程式才不會亂。

---

# 遊戲狀態 (Game State)

<br>

遊戲在任何時刻，都處於某一種「**狀態**」中：

| 狀態 | 畫面呈現 | 觸發條件 |
| :--- | :--- | :--- |
| **開始畫面** | 遊戲名稱、操作說明、按鍵提示 | 遊戲剛載入 |
| **遊戲進行中** | 玩家、敵人、分數即時更新 | 玩家按下開始鍵 |
| **暫停** | 畫面凍結，顯示「已暫停」 | 按下 ESC 或 P |
| **遊戲結束** | 最終分數、重新開始按鈕 | 玩家死亡或時間到 |

> 描述給 AI 時，把每個狀態要顯示什麼都說清楚，
> AI 才能幫你把這些切換的邏輯都接好。

---

# 狀態之間如何切換？

<br>

狀態的切換，通常由**事件**觸發：

```
              ┌──────────────┐
              │  開始畫面    │
              └──────┬───────┘
                按空白鍵開始
                     ↓
              ┌──────────────┐     碰到障礙物
              │  遊戲進行中  │ ──────────────→ ┌──────────────┐
              └──────┬───────┘                  │  遊戲結束    │
                按 ESC 暫停                      └──────┬───────┘
                     ↓                              按 R 重來
              ┌──────────────┐                       ↓
              │    暫停      │           回到「開始畫面」
              └──────────────┘
```

你要告訴 AI：**哪個鍵負責切換哪個狀態。**

---

# 遊戲中的「物件」

<br>

一個典型的遊戲由幾種基本物件組成，每個物件都有自己的屬性：

**玩家 (Player)**
位置 (x, y)、大小 (寬、高)、速度、生命值

**障礙物 / 敵人 (Obstacle)**
位置 (x, y)、大小、移動速度、是否已被消除

**道具 (Item)**
位置、效果類型（無敵？加分？加速？）、出現機率

**UI 元素**
分數、生命條、倒數計時、關卡數

> 把這些物件和它們的屬性描述給 AI，
> 就等於給了 AI 一份完整的**遊戲設計文件**。

---

# AI 幫我們做什麼？

<br>

你把遊戲的「設計圖」描述清楚，AI 負責把所有程式碼搭起來。

你負責的是：
- **遊戲類型**：閃避？點擊？解謎？
- **操作方式**：鍵盤？滑鼠？
- **視覺風格**：像素風？簡約色塊？
- **勝負條件**：怎麼算贏？怎麼算輸？
- **狀態與切換**：哪個鍵開始、哪個鍵重來？

> 你不需要寫程式，但你需要**想清楚遊戲怎麼運作**。

---

# Prompt 公式

<br>

寫遊戲 Prompt 的萬用結構：

```
用純 HTML / CSS / JavaScript（單一檔案）做一個 [遊戲類型]。

玩法：[操作方式 + 核心規則]

視覺：[風格描述]

勝負：[過關或失敗條件]

狀態：[開始畫面、暫停、結束畫面 各用什麼鍵切換]

額外要求：[分數、生命值、音效、難度遞增等]
```

**單一 HTML 檔案** 是關鍵字——讓 AI 產出一個直接打開就能玩的檔案。

---

# 範例 Prompt：閃避遊戲

<br>

> 用純 HTML / CSS / JavaScript（單一檔案）做一個閃避遊戲。
>
> 玩法：玩家在畫面底部，用左右方向鍵移動，障礙物從頂端隨機落下，碰到就扣一條命，共三條命。
>
> 視覺：黑色背景，玩家是藍色方塊，障礙物是紅色方塊。
>
> 分數：成功閃過的障礙物數量，顯示在左上角。分數越高，障礙物落下越快。
>
> 狀態：按空白鍵開始，Game Over 時顯示最終分數，按 R 重新開始。

---

# 範例 Prompt：貪吃蛇

<br>

> 用純 HTML / CSS / JavaScript（單一檔案）做一個貪吃蛇遊戲。
>
> 玩法：用方向鍵控制蛇的方向，吃到食物長一節，碰到牆壁或自己的身體就 Game Over。
>
> 視覺：深色背景，蛇是亮綠色，食物是紅色圓點，畫面有格線（棋盤風格）。
>
> 分數：每吃一個食物加 10 分，顯示在畫面上方。
>
> 狀態：按空白鍵開始，Game Over 時顯示最終分數，按 R 重新開始。

---

# 範例 Prompt：點擊遊戲

<br>

> 用純 HTML / CSS / JavaScript（單一檔案）做一個點擊反應遊戲。
>
> 玩法：畫面上隨機出現彩色圓圈，玩家要在它消失前用滑鼠點擊，點到加分，沒點到扣一條命，共三條命。
>
> 視覺：白色背景，圓圈顏色隨機，大小也隨機。分數越高，圓圈出現越快、消失越快。
>
> 額外：有 30 秒倒數計時模式，時間到顯示最終得分。
>
> 狀態：點擊「開始」按鈕進入遊戲，結束後有重玩按鈕。

---

# 追加修改的 Prompt 技巧

<br>

第一版出來後，**直接追加要求**，不要重新生成：

- 「幫我把背景改成星空，玩家改成一艘太空船」
- 「分數每加到 10 的倍數，障礙物速度提升 0.5」
- 「加一個無敵道具（黃色星星），碰到後無敵 3 秒」
- 「Game Over 時加上畫面抖動效果」
- 「加上簡單音效（用 Web Audio API 自動生成，不需要音效檔）」

> 把 AI 當成坐在你旁邊的工程師，**不斷給反饋、不斷修改**。
